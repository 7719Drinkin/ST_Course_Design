# 前端展示对接文档

## 1. 文档目标

本文档面向 C 前端负责人，用于明确 AutoTestDesign 的前端页面需要接收什么输入、展示什么内容、允许设计者修改什么内容，以及每个页面对应的后端接口。

前端的核心目标不是展示静态结果，而是让设计者完成以下交互式测试设计链路：

```text
需求输入
-> 结构化解析
-> 概念识别
-> 风险评分
-> 覆盖项识别
-> 覆盖策略选择
-> 测试用例生成
-> 人工审查与修订
-> 差量再生成
-> 结果分析
-> 导出
```

所有展示对象必须围绕 AUT `LibraryManagementSystem`，不能把 AutoTestDesign 本身作为测试对象。

## 2. 页面与接口总览

| 页面或模块 | 设计者输入 | 前端展示 | 后端接口 | 关键请求/返回字段 |
|---|---|---|---|---|
| 需求输入页 | 文本粘贴或文件上传 | 上传状态、输入预览、写入成功或失败提示 | `POST /ingest`、`POST /ingest/file` | 文本请求 `content: string`；文件请求 `file: file`；成功均返回 `204 No Content` |
| 结构化解析页 | 选择需求、触发解析 | 输入字段、数据范围、条件、期望行为、置信度 | `POST /parse` | 请求 `requirement_ids`；返回 `parsed_requirements`、`prompt_evidence` |
| 概念识别页 | 选择解析结果 | 业务对象、业务操作、状态、约束、证据 | `POST /concepts` | 返回 `concepts` |
| 风险分析页 | 选择需求或覆盖项 | Impact、Likelihood、Risk Score、Risk Level、Test Priority、风险热力图 | `POST /risk` | 请求 `targets`；返回 `risk_results` |
| 覆盖项页 | 选择需求、概念、风险结果 | `COV-AUT-*`、覆盖项描述、来源需求、状态 | `POST /coverage` | 返回 `coverage_items` |
| 覆盖策略页 | 选择覆盖项 | EP、BVA、DT、FSM、选择理由、标准依据 | `POST /strategy` | 返回 `strategies` |
| 测试用例页 | 选择覆盖项和策略 | `TC-AUT-*`、前置条件、步骤、输入、期望结果、追踪关系 | `POST /generate` | 返回 `test_cases` |
| FSM 页面 | 选择状态相关需求或覆盖项 | 状态、迁移、覆盖路径、Mermaid 图、FSM 测试用例 | `POST /fsm` | 返回 `fsm`、`test_cases` |
| Prompt 证据页 | 选择生成步骤 | Prompt 模板、输入、RAG 上下文、模型输出摘要 | 由 `/parse`、`/coverage`、`/strategy`、`/generate`、`/oracle`、`/regenerate` 返回 | 返回 `prompt_evidence` |
| Revision 面板 | 修改覆盖项、策略、用例、风险分数 | 修改前后内容、修改原因、影响范围 | `POST /revisions` | 请求 `target_type`、`before`、`after`；返回 `revision`、`affected_ids` |
| 差量再生成入口 | 选择一个 `revision_id` | 受影响项、新增或更新用例、变更说明 | `POST /regenerate` | 返回 `created`、`updated`、`unchanged`、`deprecated` |
| 结果分析页 | 选择当前设计会话 | 需求、覆盖项、策略、用例之间的映射、遗漏项、改进项 | `POST /analysis` | 返回 `analysis_results`、`summary` |
| 测试套件优化页 | 选择测试用例集合和优化目标 | 保留用例、删除用例、覆盖保持说明、优化前后对比 | `POST /optimize` | 请求 `objective`；返回 `optimization_result` |
| 导出页 | 选择导出格式 | 导出预览、字段完整性、下载状态 | `GET /export` 或 `POST /export` | 返回 `file` 或 `export_bundle` |

## 3. 前端必须支持的输入

| 输入类型 | 前端要求 | 校验要求 | 交给后端的字段与类型 |
|---|---|---|---|
| 文本粘贴 | 多行文本框，显示文本预览 | 非空、长度提示 | `POST /ingest`，JSON 字段 `content: string` |
| TXT/MD 文件 | 文件上传，显示文件名和文件大小 | 文件类型、空文件、编码错误 | `POST /ingest/file`，multipart 字段 `file: file` |
| PDF 文件 | 文件上传，显示文件名和文件大小 | 文件类型、空文件、解析依赖可用性 | `POST /ingest/file`，multipart 字段 `file: file` |
| DOCX 文件 | 文件上传，显示文件名和文件大小 | 文件类型、空文件、解析依赖可用性 | `POST /ingest/file`，multipart 字段 `file: file` |
| DOC 文件 | 前端可提示转换为 DOCX 或 PDF | 后续解析阶段当前不支持 `.doc` | 不建议提交；若提交仍只能走 `POST /ingest/file`，multipart 字段 `file: file` |

前端不负责解析文件语义。文本输入调用 `POST /ingest`，文件上传调用 `POST /ingest/file`；两个接口成功时均无 JSON 返回体。需求列表、结构化字段和错误项应由后续解析流程产生，不能从 ingest 阶段读取。

## 4. 前端必须展示的数据对象

| 数据对象 | 必须展示字段与类型 | 是否可编辑 | 编辑接口 |
|---|---|---|---|
| Requirement | `requirement_id: string`、`raw_requirement: string`、`source: string`、`source_type: enum` | 原始内容原则上只读 | 如需修改，走 `POST /revisions` |
| ParsedRequirement | `input_fields: array<string>`、`data_ranges: array<string>`、`conditions: array<string>`、`expected_action: string`、`confidence: number`、`missing_fields: array<string>` | 可编辑 | `POST /revisions` |
| Concept | `concept_id: string`、`name: string`、`type: enum<object, operation, state, constraint>`、`evidence: string` | 可标记有效性 | `POST /revisions` |
| RiskResult | `impact: number`、`likelihood: number`、`risk_score: number`、`risk_level: enum<Low, Medium, High>`、`test_priority: enum<P1, P2, P3>`、`reason: string` | 可调整 | `POST /revisions` |
| CoverageItem | `coverage_item_id: string`、`requirement_id: string`、`description: string`、`technique: enum<EP, BVA, DT, FSM>`、`status: enum<ai_generated, human_revised, human_added, rejected>` | 可新增、修改、删除、标记有效 | `POST /revisions` |
| Strategy | `strategy_id: string`、`coverage_item_id: string`、`technique: enum<EP, BVA, DT, FSM>`、`standard_ref: string`、`reason: string`、`algorithm_params: object` | 可编辑 | `POST /revisions` |
| TestCase | `test_id: string`、`requirement_id: string`、`coverage_item_id: string`、`test_steps: array<string>`、`expected_result: string`、`status: enum<Draft, Approved, Rejected>` | 可编辑 | `POST /revisions` |
| PromptEvidence | `prompt_template_id: string`、`prompt_inputs: object`、`source_context_ids: array<string>`、`model_name: string`、`output_schema_version: string` | 只读 | 无 |
| RevisionRecord | `revision_id: string`、`target_type: string`、`target_id: string`、`before: object`、`after: object`、`reason: string` | 只读 | 无 |
| AnalysisResult | `requirement_id: string`、`coverage_item_id: string`、`test_id: string`、`status: enum<covered, missing, improved, needs_review>`、`gap: string`、`improvement: string` | 只读或备注 | 可通过 `POST /revisions` 新增改进项 |

## 5. 交互式修改要求

前端必须支持设计者至少修改以下三类设计项：

1. 覆盖项：新增、删除、修改描述、标记有效或无效。
2. 覆盖策略：把一个覆盖项从 EP 改为 BVA、DT 或 FSM，或修改策略理由。
3. 测试用例：修改步骤、输入数据、期望结果、风险等级或状态。

每次修改必须提交：

```json
{
  "session_id": "SESSION-*",
  "target_type": "coverage_item | strategy | test_case | risk_result",
  "target_id": "COV-AUT-*",
  "before": {},
  "after": {},
  "reason": "设计者修改原因",
  "created_by": "designer"
}
```

前端不得只在本地状态中修改数据而不调用 `POST /revisions`。没有 `revision_id` 的修改不能作为最终文档中的“基于证据的改进”。

## 6. 前端展示状态要求

| 状态 | 展示要求 |
|---|---|
| loading | 每个长任务接口必须有加载状态，尤其是 `/parse`、`/coverage`、`/generate`、`/fsm`、`/regenerate` |
| error | 展示后端错误信息、错误字段和建议操作 |
| empty | 没有输入或没有生成结果时展示空状态，不使用假数据伪装成功 |
| partial success | 有部分需求解析失败时展示成功项和失败项 |
| revision pending | 人工修改后展示是否已保存 Revision |
| regenerated | 差量再生成后展示新增、更新、未变化的对象 |

## 7. 前端不负责的内容

- 不负责 RAG、LLM、Prompt 的实现。
- 不负责 EP、BVA、DT、FSM 算法。
- 不负责后端数据持久化。
- 不负责 AUT pytest 执行。
- 不决定测试套件优化中最终删除或保留哪些用例。
