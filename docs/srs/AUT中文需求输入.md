# LibraryManagementSystem 原始需求


系统中的数据保存在运行期内存中。服务重启后，图书、会员和借阅记录数据会被清空。系统当前不要求用户登录，也不区分不同用户权限。

系统应管理图书信息。每本图书应包含图书 ID、书名、作者、出版年份、图书类别和可借副本数量。图书 ID 由系统生成。客户端可以查询所有图书，也可以根据图书 ID 查询指定图书。

客户端可以创建新图书。创建图书时，客户端需要提交书名、作者、出版年份、图书类别和可借副本数量。系统创建成功后，应保存该图书，并为该图书生成唯一 ID。

客户端可以根据图书 ID 更新已有图书的信息。更新内容包括书名、作者、出版年份、图书类别和可借副本数量。如果指定图书不存在，系统不应创建新的图书。

客户端可以根据图书 ID 删除已有图书。图书删除后，客户端再次根据该 ID 查询时，不应再获得该图书记录。

系统应管理会员信息。每个会员应包含会员 ID、姓名、邮箱、电话号码、会员开始日期和会员结束日期。会员 ID 由系统生成。客户端可以查询所有会员，也可以根据会员 ID 查询指定会员。

客户端可以创建新会员。创建会员时，客户端需要提交姓名、邮箱、电话号码、会员开始日期和会员结束日期。系统创建成功后，应保存该会员，并为该会员生成唯一 ID。

客户端可以根据会员 ID 更新已有会员的信息。更新内容包括姓名、邮箱、电话号码、会员开始日期和会员结束日期。如果指定会员不存在，系统不应创建新的会员。

客户端可以根据会员 ID 删除已有会员。会员删除后，客户端再次根据该 ID 查询时，不应再获得该会员记录。

系统应管理借阅记录。每条借阅记录应包含借阅记录 ID、图书信息、会员信息、借出日期、应还日期和归还日期。借阅记录 ID、借出日期和应还日期由系统生成。客户端可以查询所有借阅记录。

客户端可以为一个已存在会员借阅一本已存在图书。借书请求中应包含图书 ID 和会员 ID。只有当图书存在、会员存在并且图书可借副本数量大于 0 时，系统才应创建借阅记录。

当借书成功时，系统应记录当天作为借出日期，并将应还日期设置为借出日期之后 14 天。新借阅记录的归还日期应为空。借书成功后，被借图书的可借副本数量应减少 1。

如果借书请求中的图书 ID 缺失，或者图书 ID 不对应任何已存在图书，系统应拒绝该借书请求，并且不应创建借阅记录。

如果借书请求中的会员 ID 缺失，或者会员 ID 不对应任何已存在会员，系统应拒绝该借书请求，并且不应创建借阅记录。

如果目标图书的可借副本数量为 0，系统应拒绝借书请求。拒绝借书后，系统不应创建借阅记录，也不应把图书可借副本数量减少为负数。

客户端可以归还一本已借出的图书。归还请求通过借阅记录 ID 指定要归还的借阅记录。只有当借阅记录存在，并且该借阅记录尚未归还时，系统才应完成归还。

当归还成功时，系统应记录当天作为归还日期，并将对应图书的可借副本数量增加 1。

如果归还请求中的借阅记录 ID 不存在，系统应拒绝该归还请求。

如果某条借阅记录已经归还，客户端再次提交同一借阅记录的归还请求时，系统应拒绝重复归还。

系统的接口请求和响应主要使用 JSON。创建和更新图书、创建和更新会员、借书等请求需要提交 JSON 请求体。如果客户端提交格式错误、无法解析的 JSON，请求应被拒绝。

系统应使用常见 HTTP 状态码表达处理结果。成功查询或更新通常返回成功状态，成功创建资源返回创建成功状态，成功删除资源返回无内容状态，输入错误或业务规则不满足时返回请求错误状态，按 ID 查询、更新或删除不存在的资源时返回未找到状态。

系统中的日期字段使用 `YYYY-MM-DD` 格式。借阅记录中的应还日期应始终晚于借出日期 14 天。

图书借阅流程可以被理解为状态变化：图书最初处于可借状态；借书成功后产生未归还借阅记录；归还成功后借阅记录关闭，图书重新变为可借；当图书没有可借副本、图书或会员不存在、借阅记录不存在或重复归还时，请求进入被拒绝结果。

系统当前不提供结构化错误响应体，因此错误场景主要通过 HTTP 状态码判断。系统当前也不强制校验邮箱格式、字符串长度或所有数值范围。
