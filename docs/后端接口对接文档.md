# 后端接口对接文档

## 1. 文档目标

本文档面向 A 后端负责人，用于明确后端需要为前端提供哪些 endpoint、每个 endpoint 的输入字段、返回字段、字段类型、业务逻辑，以及如何对接 B 的 RAG/Prompt 能力和 E 的测试设计算法。

后端职责是接口封装、请求校验、响应包装、数据持久化和流程编排。后端不负责 Prompt 设计，也不负责 EP、BVA、DT、FSM 的核心算法。

## 2. 通用字段类型约定

| 类型写法 | 含义 |
|---|---|
| `string` | 字符串 |
| `number` | 数值，包含整数和小数 |
| `boolean` | 布尔值 |
| `object` | JSON 对象 |
| `array<T>` | T 类型数组 |
| `enum<...>` | 枚举值，只能从列出的值中选择 |
| `file` | multipart 文件 |
| `binary` | 二进制文件流 |

通用 ID 规则：

| ID | 示例 | 含义 |
|---|---|---|
| `session_id` | `SESSION-001` | 一次测试设计会话 |
| `requirement_id` | `REQ-AUT-001` | AUT 需求 |
| `concept_id` | `CON-AUT-001` | AUT 概念 |
| `coverage_item_id` | `COV-AUT-001` | 覆盖项 |
| `strategy_id` | `STR-AUT-001` | 覆盖策略 |
| `test_id` | `TC-AUT-001` | 测试用例 |
| `revision_id` | `REV-001` | 人工修订记录 |
| `prompt_template_id` | `PROMPT-PARSE-001` | Prompt 模板 |

## 3. Endpoint 设计

### 3.1 `POST /ingest`

**业务目标：** 接收设计者粘贴的需求文本，将原始文本写入后端暂存区，供后续解析流程读取。当前代码不在该接口中拆分需求、不生成 `REQ-AUT-*`，也不返回需求列表。

**请求格式：** `application/json`

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `content` | `string` | 否 | 文本内容；后端 schema 默认值为空字符串。前端应在提交前校验非空。 |

**返回字段：**

| HTTP 状态码 | 返回体 | 说明 |
|---|---|---|
| `204 No Content` | 无 | 写入成功；当前接口不返回 JSON。 |

**业务逻辑：**

1. 读取 JSON 中的 `content` 字段。
2. 将 `content` 按 UTF-8 编码为 `bytes`。
3. 调用 `ingest_manager.ingest(...)` 写入后端暂存文件。
4. 返回 `204 No Content`。
5. 当前代码不做需求拆分、ID 生成、会话保存或错误项列表返回。

**文件上传补充入口：** 当前代码另有 `POST /ingest/file`，用于文件上传。它不属于 `POST /ingest` 的 JSON 请求体，但前端文件上传应调用该入口。

`POST /ingest/file` 请求格式：`multipart/form-data`

`POST /ingest/file` 请求字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | `file` | 是 | multipart 文件字段；后端读取原始 `bytes`，并根据文件名后缀记录格式。 |

`POST /ingest/file` 返回字段：

| HTTP 状态码 | 返回体 | 说明 |
|---|---|---|
| `204 No Content` | 无 | 写入成功；当前接口不返回 JSON。 |

文件解析说明：

1. `.txt`、`.md` 按 UTF-8 文本解析。
2. `.pdf` 依赖 `pymupdf`。
3. `.docx` 依赖 `python-docx`。
4. `.doc` 当前解析器会抛出 `NotImplementedError`。
5. 未注册后缀会按 UTF-8 容错解码。

**B/E 对接：** 不调用 B 或 E。

### 3.2 `POST /parse`

**业务目标：** 对 Requirement 进行结构化解析。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `requirement_ids` | `array<string>` | 否 | 需要解析的需求 ID；为空时解析当前会话全部需求 |
| `requirements` | `array<Requirement>` | 否 | 可选，直接传入需求对象 |
| `include_prompt_evidence` | `boolean` | 否 | 是否返回 PromptEvidence，默认 `true` |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `parsed_requirements` | `array<ParsedRequirement>` | 结构化解析结果 |
| `prompt_evidence` | `array<PromptEvidence>` | 本次 LLM 调用证据 |
| `errors` | `array<ApiError>` | 解析失败项 |

**`ParsedRequirement` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `requirement_id` | `string` | 对应 Requirement |
| `input_fields` | `array<string>` | 输入字段 |
| `data_ranges` | `array<string>` | 数据范围或边界 |
| `conditions` | `array<string>` | 条件和约束 |
| `expected_action` | `string` | 期望行为 |
| `confidence` | `number` | 0 到 1 的置信度 |
| `missing_fields` | `array<string>` | 缺失或不确定字段 |

**业务逻辑：**

1. 读取 Requirement。
2. 调用 B 的 requirement parse Prompt。
3. 校验 `input_fields`、`data_ranges`、`conditions`、`expected_action` 是否存在。
4. 保存 ParsedRequirement 和 PromptEvidence。
5. 返回解析结果。

**B/E 对接：** 调用 B；不调用 E。

### 3.3 `POST /concepts`

**业务目标：** 从 AUT 需求中识别业务概念。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `requirement_ids` | `array<string>` | 否 | 概念识别范围 |
| `parsed_requirements` | `array<ParsedRequirement>` | 否 | 可选，直接传入解析结果 |
| `include_evidence` | `boolean` | 否 | 是否返回证据，默认 `true` |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `concepts` | `array<Concept>` | AUT 概念 |
| `prompt_evidence` | `array<PromptEvidence>` | Prompt 证据 |

**`Concept` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `concept_id` | `string` | `CON-AUT-*` |
| `requirement_id` | `string` | 来源需求 |
| `name` | `string` | 概念名称，如 Book、Member |
| `type` | `enum<object, operation, state, constraint>` | 概念类型 |
| `evidence` | `string` | 来自需求或 RAG 的证据 |

**业务逻辑：**

1. 输入 Requirement 和 ParsedRequirement。
2. 调用 B 的 concept extraction Prompt。
3. 保存 Concept。
4. 返回业务对象、操作、状态、约束和证据。

**B/E 对接：** 调用 B；不调用 E。

### 3.4 `POST /risk`

**业务目标：** 对 AUT 需求或覆盖项进行风险评分。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `targets` | `array<RiskTarget>` | 是 | 评分对象 |
| `risk_matrix_version` | `string` | 否 | 风险矩阵版本 |

**`RiskTarget` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `target_id` | `string` | `REQ-AUT-*`、`FR-AUT-*` 或 `COV-AUT-*` |
| `target_type` | `enum<requirement, coverage_item>` | 评分对象类型 |
| `text` | `string` | 需求或覆盖项文本 |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `risk_results` | `array<RiskResult>` | 风险评分结果 |
| `prompt_evidence` | `array<PromptEvidence>` | Prompt 证据 |

**`RiskResult` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `target_id` | `string` | 被评分对象 ID |
| `target_type` | `enum<requirement, coverage_item>` | 被评分对象类型 |
| `impact` | `number` | 1 到 5 |
| `likelihood` | `number` | 1 到 5 |
| `risk_score` | `number` | `impact * likelihood` |
| `risk_level` | `enum<Low, Medium, High>` | 风险等级 |
| `test_priority` | `enum<P1, P2, P3>` | 测试优先级 |
| `reason` | `string` | 评分理由 |
| `evidence` | `array<string>` | 支撑证据 |

**业务逻辑：**

1. 校验评分对象只能是 `REQ-AUT-*`、`FR-AUT-*` 或 `COV-AUT-*`。
2. 调用 B 的 risk scoring Prompt 和风险矩阵。
3. 保存 RiskResult。
4. 返回风险等级、测试优先级和理由。

**B/E 对接：** 调用 B；不调用 E。E 只消费风险结果。

### 3.5 `POST /coverage`

**业务目标：** 生成并规范化覆盖项。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `parsed_requirements` | `array<ParsedRequirement>` | 否 | 可选，结构化需求 |
| `concepts` | `array<Concept>` | 否 | 可选，概念识别结果 |
| `risk_results` | `array<RiskResult>` | 否 | 可选，风险评分结果 |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `coverage_items` | `array<CoverageItem>` | 规范化覆盖项 |
| `prompt_evidence` | `array<PromptEvidence>` | 覆盖项候选 Prompt 证据 |

**`CoverageItem` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `coverage_item_id` | `string` | `COV-AUT-*` |
| `requirement_id` | `string` | 来源需求 |
| `description` | `string` | 覆盖项描述 |
| `technique` | `enum<EP, BVA, DT, FSM>` | 推荐或当前测试技术 |
| `strategy` | `string` | 覆盖策略摘要 |
| `status` | `enum<ai_generated, human_revised, human_added, rejected>` | 覆盖项状态 |
| `source` | `enum<llm, algorithm, designer>` | 来源 |

**业务逻辑：**

1. 将解析结果、概念、风险结果传给 B。
2. B 返回候选覆盖项和理由。
3. 调用 E 做去重、编号和结构化。
4. 保存 CoverageItem。
5. 返回 `COV-AUT-*` 覆盖项列表。

**B/E 对接：** 先调用 B，再调用 E。

### 3.6 `POST /strategy`

**业务目标：** 为覆盖项分配测试策略。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `coverage_items` | `array<CoverageItem>` | 是 | 待分配策略的覆盖项 |
| `risk_results` | `array<RiskResult>` | 否 | 风险结果 |
| `parsed_requirements` | `array<ParsedRequirement>` | 否 | 结构化需求 |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `strategies` | `array<Strategy>` | 策略结果 |
| `prompt_evidence` | `array<PromptEvidence>` | 策略 Prompt 证据 |

**`Strategy` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `strategy_id` | `string` | `STR-AUT-*` |
| `coverage_item_id` | `string` | 对应覆盖项 |
| `technique` | `enum<EP, BVA, DT, FSM>` | 测试技术 |
| `standard_ref` | `string` | 标准依据 |
| `reason` | `string` | 选择理由 |
| `algorithm_params` | `object` | E 可执行的算法参数 |

**业务逻辑：**

1. 输入 CoverageItem、RiskResult、ParsedRequirement。
2. 调用 B 生成策略建议和标准依据。
3. 调用 E 转换为算法可执行参数。
4. 保存 Strategy。
5. 返回 technique、standard_ref、reason 和 algorithm_params。

**B/E 对接：** 先调用 B，再调用 E。

### 3.7 `POST /generate`

**业务目标：** 生成可追踪测试用例。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `coverage_items` | `array<CoverageItem>` | 是 | 覆盖项 |
| `strategies` | `array<Strategy>` | 是 | 策略 |
| `parsed_requirements` | `array<ParsedRequirement>` | 是 | 结构化需求 |
| `risk_results` | `array<RiskResult>` | 否 | 风险结果 |
| `generation_mode` | `enum<full, incremental>` | 否 | 生成模式，默认 `full` |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `test_cases` | `array<TestCase>` | 生成的测试用例 |
| `prompt_evidence` | `array<PromptEvidence>` | 可选，LLM 草案或 Oracle 证据 |

**`TestCase` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `test_id` | `string` | `TC-AUT-*` |
| `requirement_id` | `string` | 来源需求 |
| `coverage_item_id` | `string` | 来源覆盖项 |
| `strategy_id` | `string` | 来源策略 |
| `technique` | `enum<EP, BVA, DT, FSM>` | 测试技术 |
| `preconditions` | `array<string>` | 前置条件 |
| `input_data` | `object` | 测试输入 |
| `test_steps` | `array<string>` | 测试步骤 |
| `expected_result` | `string` | 期望结果 |
| `standard_ref` | `string` | 标准依据 |
| `risk_level` | `enum<Low, Medium, High>` | 关联风险 |
| `status` | `enum<Draft, Approved, Rejected>` | 设计者审查状态 |

**业务逻辑：**

1. 读取 CoverageItem、Strategy、ParsedRequirement、RiskResult。
2. 按 technique 调用 E 的 EP、BVA、DT 或 FSM 生成器。
3. 若需要 expected_result 或标准依据补充，调用 B 的 Prompt 或 Oracle。
4. 为每条测试用例生成 `TC-AUT-*`。
5. 校验每条用例必须包含 `requirement_id` 和 `coverage_item_id`。
6. 保存 TestCase。

**B/E 对接：** 主调用 E；必要时调用 B。

| `coverage_items` | `array<CoverageItem>` | 否 | 状态相关覆盖项 |

**`FsmResult` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `states` | `array<string>` | 状态集合 |

**业务逻辑：**

3. 调用 E 的 FSM 建模器生成 states、transitions、coverage_paths。
4. 生成 Mermaid 图描述文本。
5. 返回 FSM 测试用例。

**B/E 对接：** 可调用 B；主调用 E。

### 3.10 `POST /revisions`

**业务目标：** 保存设计者人工修改。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `target_type` | `enum<requirement, parsed_requirement, risk_result, coverage_item, strategy, test_case>` | 是 | 修改对象类型 |
| `target_id` | `string` | 是 | 修改对象 ID |
| `before` | `object` | 是 | 修改前字段 |
| `after` | `object` | 是 | 修改后字段 |
| `reason` | `string` | 是 | 修改原因 |
| `created_by` | `string` | 是 | 修改者，通常为 `designer` |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `revision` | `RevisionRecord` | 新增修订记录 |
| `affected_ids` | `array<string>` | 受影响对象 ID |

**`RevisionRecord` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `revision_id` | `string` | `REV-*` |
| `session_id` | `string` | 设计会话 ID |
| `target_type` | `string` | 修改对象类型 |
| `target_id` | `string` | 修改对象 ID |
| `before` | `object` | 修改前 |
| `after` | `object` | 修改后 |
| `reason` | `string` | 修改原因 |
| `created_by` | `string` | 修改者 |

5. 返回受影响对象列表。

**B/E 对接：** 不直接调用 B/E；`/regenerate` 消费 RevisionRecord。

| `prompt_evidence` | `array<PromptEvidence>` | revision Prompt 证据 |

**业务逻辑：**

1. 读取 `revision_id`。
2. 分析受影响的需求、覆盖项、策略和测试用例。
3. 调用 B 重新解释修改影响。
4. 调用 E 只生成受影响用例。
5. 返回新增、更新、未变化和建议废弃对象。

**B/E 对接：** 先调用 B，再调用 E。

### 3.12 `POST /analysis`

**业务目标：** 生成结果分析和映射关系。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `requirements` | `array<Requirement>` | 否 | 可选，需求列表 |
| `coverage_items` | `array<CoverageItem>` | 否 | 可选，覆盖项 |
| `strategies` | `array<Strategy>` | 否 | 可选，策略 |
| `test_cases` | `array<TestCase>` | 否 | 可选，测试用例 |
| `revisions` | `array<RevisionRecord>` | 否 | 可选，修订记录 |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `analysis_results` | `array<AnalysisResult>` | 映射和缺口分析 |
| `summary` | `AnalysisSummary` | 汇总统计 |

**`AnalysisResult` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `requirement_id` | `string` | 需求 ID |
| `coverage_item_id` | `string` | 覆盖项 ID |
| `strategy_id` | `string` | 策略 ID |
| `test_id` | `string` | 测试用例 ID |
| `status` | `enum<covered, missing, improved, needs_review>` | 分析状态 |
| `gap` | `string` | 缺口说明 |
| `improvement` | `string` | 改进说明 |

**`AnalysisSummary` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `requirements_count` | `number` | 需求数量 |
| `coverage_items_count` | `number` | 覆盖项数量 |
| `test_cases_count` | `number` | 测试用例数量 |
| `missing_count` | `number` | 缺口数量 |
| `improved_count` | `number` | 改进数量 |

**业务逻辑：**

1. 汇总 Requirement、CoverageItem、Strategy、TestCase、RevisionRecord。
2. 生成 `REQ-AUT-* -> COV-AUT-* -> TC-AUT-*` 映射。
3. 标记已覆盖、未覆盖、需改进项。
4. 返回 AnalysisResult。

**B/E 对接：** 可消费 E 的结构化映射；通常不调用 B。

### 3.13 `POST /optimize`

**业务目标：** 进行测试套件优化。

**请求字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `session_id` | `string` | 是 | 设计会话 ID |
| `test_cases` | `array<TestCase>` | 是 | 待优化测试用例 |
| `coverage_items` | `array<CoverageItem>` | 是 | 覆盖项 |
| `risk_results` | `array<RiskResult>` | 是 | 风险结果 |
| `objective` | `enum<set_cover, risk_priority>` | 是 | 优化目标 |
| `preserve_high_risk_unique_coverage` | `boolean` | 否 | 是否强制保留高风险唯一覆盖，默认 `true` |

**返回字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `session_id` | `string` | 设计会话 ID |
| `optimization_result` | `OptimizationResult` | 优化结果 |

**`OptimizationResult` 字段：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `objective` | `enum<set_cover, risk_priority>` | 优化目标 |
| `before_count` | `number` | 优化前用例数 |
| `after_count` | `number` | 优化后建议保留用例数 |
| `kept_test_ids` | `array<string>` | 建议保留用例 |
| `removed_test_ids` | `array<string>` | 建议删除用例 |
| `coverage_preservation` | `array<string>` | 覆盖保持说明 |
| `warnings` | `array<string>` | 风险提示 |

**业务逻辑：**

1. 接收测试用例集合、风险等级、覆盖关系和优化目标。
2. 调用 E 的 set cover 或风险排序算法。
3. 返回保留用例、删除候选、覆盖保持说明。
4. 保存 D 最终接受或拒绝的优化结果。

**B/E 对接：** 主调用 E；B 可选补充风险解释。

**返回字段：**

## 4. 后端与 B/E 的调用关系

| 后端接口 | 调用 B | 调用 E |
|---|---|---|
| `/ingest`、`/ingest/file` | 不调用 | 不调用 |
| `/parse` | 结构化解析 Prompt | 不调用 |
| `/concepts` | 概念识别 Prompt | 不调用 |
| `/risk` | 风险评分 Prompt | 不调用 |
| `/coverage` | 覆盖项候选 Prompt | 覆盖项规范化 |
| `/strategy` | 策略建议 Prompt | 策略参数化 |
| `/generate` | 可选测试用例草案、Oracle、标准依据 | EP、BVA、DT、FSM 生成器 |
| `/fsm` | 可选状态语义辅助 | FSM 建模器 |
| `/oracle` | Oracle Prompt | 不调用 |
| `/revisions` | 不调用 | 不调用 |
| `/regenerate` | revision Prompt | 差量生成 |
| `/analysis` | 通常不调用 | 可消费结构化映射 |
| `/optimize` | 可选风险解释 | 优化候选算法 |
| `/export` | 不调用 | 不调用 |

## 5. 后端错误响应要求

错误响应必须包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `error_code` | `string` | 错误码，如 `VALIDATION_ERROR` |
| `message` | `string` | 错误说明 |
| `field` | `string` | 可选，出错字段 |
| `details` | `object` | 可选，错误上下文 |

`ApiError` 与错误响应使用同一字段结构；endpoint 内的 `errors: array<ApiError>` 表示局部失败项，不代表整个请求失败。

不得只返回空字符串或未处理异常栈。
